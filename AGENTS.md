# Notes projet (pour les agents et les humains)

- Plateforme multi-pages Vite 7 + Three.js 0.170, modules ES, DOM natif, aucun framework UI. Langue du code/UI : français.
- Commandes : `npm run dev` (port 5173), `npm test` (node --test, logique uniquement), `npm run build`, `npm start` (sert `dist/`). À exécuter **dans WSL** (`nvm use` — `.nvmrc` épingle Node 22, ≥ 20.19 requis par Vite 7) : depuis Windows le projet est sur `\\wsl.localhost\…`, chemin UNC que CMD ne gère pas et qui casse la résolution des entrées Rollup (`Could not resolve entry module`). Les scripts npm invoquent `node node_modules/vite/bin/vite.js` pour contourner les shims `.bin/` générés par Windows (qui relancent `node.exe` sous WSL).
- `vite.config.js` : `root = src/`. Pages : hub (`src/index.html`) et `src/games/<jeu>/index.html`. Un nouveau jeu = page dans `pages` + entrée dans `src/shared/games.js` (source unique du catalogue, du SEO et des planètes du hub).
- Code commun dans `src/shared/` (createRenderer, loop, Keyboard, Music, SoundBox, events/Emitter, loadTextures, canvasTexture, chrome). Ne pas dupliquer ces briques dans un jeu.
- Séparation stricte : tout dossier `core/` (hub, pixel) ne doit importer ni Three.js ni le DOM. Le rendu écoute les évènements émis par la logique (`Emitter`), documentés en tête du fichier de règles.
- Toujours ajouter un test dans `tests/` quand une règle change.
- Hub : repère x droite / y haut. Commandes : ↑ avancer, ↓ demi-tour, ←/→ tourner, Espace tirer. L'entrée en orbite ouvre une modale (`ui/OrbitModal.js`), le jeu est lancé uniquement via `SpaceGame.enterGame()`.
- PIXEL : axes X gauche/droite, **Y = hauteur** (0 = sol), Z = profondeur. Cartes finies bordées de murs, un fichier par niveau (`levels/levelN.js`). Aucun contrôle clavier (tout passe par le terminal), gravité obligatoire (`Rules.settle`).
- PIXEL niveaux : 9 niveaux déterministes (plus de `random`), chacun avec `tests` (variantes : carte/balles/objectif remplacés, `budget` = pas max en multiple du plus court chemin). `getLevelDef(n, test)` : test 0 = niveau de base. Le niveau réinitialise offsets (`offsets`) et balles (valeur exacte). Cartes ASCII : chiffres 2-9 = tour de violets, helpers `solidMap/carve/transpose/mirrorX/mirrorZ` dans `levels/builder.js`.
- PIXEL scanner : `core/scan.js` (portée = 1 + jaunes empilés sur le rouge), exposé par `Scanner` / `ScannerRange`. Le déplacement se fait uniquement avec `move(x, z)` (pas de `run`, pas de tableau tapé) ; `move/fire/moveYellow/wait` renvoient une promesse résolue à l'exécution du pas (`await move(...)` dans une fonction async pour réagir). Mode test : `api/levelTests.js` (jeu headless + sauvegarde `localStorage` `pixel.levelTests.v1`), modale `ui/LevelsModal.js`. Page d'aide : `games/pixel/aide/` (entrée `pixelAide` dans `vite.config.js`). Solutions de référence de chaque niveau dans `tests/pixelLevels.test.js`.
- Pirates : paramètres de jeu dans `config.js`, un module par responsabilité (bateau, ennemis, bataille, carte, ui).
- Images/audio dans `public/` (servis à la racine). Notes d'origine et ressources non utilisées dans `docs/`.
- PIXEL : un violet ne se détruit que par une balle ou par écrasement (un cube jaune qui le percute, avec un autre jaune juste au-dessus qui retombe dessus). Pas de règle « sandwich ».
- Inventeurs : règles dans le bloc `GAME` de `games/inventeurs/main.js`, données dans `inventions.js`, géométrie générée (`node scripts/buildWorld.mjs` depuis `public/images/world.svg`, ne pas éditer `worldGeo.js`). Déplacements via `shared/ShipPhysics.js` (identiques au hub).
- Style commun parchemin/croquis : `shared/theme.css` + `shared/theme.js` (polices) + filtre SVG `#wobble` à mettre dans chaque page ; dessins canvas dans `shared/sketch.js`.
